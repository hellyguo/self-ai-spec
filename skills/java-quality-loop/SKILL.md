# Java 代码质量防腐循环（Java Code Quality Loop）

> 本文件中的 `templates/...`、`scripts/...`、`references/...` 均指本技能目录下的对应子目录。

> **适用范围**：本技能是 Java 特化版本，默认使用 Maven/Gradle、JUnit、Java 源码扫描与 JVM 构建/测试命令。非 Java 项目请替换扫描器、构建与测试命令后再使用；不要直接套用 Java 的模块/依赖/测试假设。

## 1. 定位与边界

本技能是**执行型循环 SOP**，用于把“持续重构、防止腐化”变成可周期性运行、可量化、可回滚的工程活动。

| 技能 | 职责 | 与本技能的关系 |
|---|---|---|
| `lets-loop` | 循环系统设计（L1–L4、调度、预算、状态） | 本技能是其代码质量领域的专用实现 |
| `long-term-task` | 单次长任务执行协议（澄清、计划、连续执行） | 单轮执行可套用；本技能补充跨轮状态与周期退出 |
| `code-refactor` | 重构方法论（退化识别、三问分析、策略） | 本技能把方法论落地为轮次 SOP |
| `code-review` | 审查框架与分级 | 每轮提交前的审查门禁 |
| `code-detect-dup` | Simian/JSCPD 重复检测 | 周期级指标与扫描输入 |
| `code-part-modification` | 最小改动、影响分析、蝴蝶效应检查 | 每轮改动必须遵循 |
| `java-coverage` | 单元测试与覆盖率 | 每轮测试补充与验证 |
| `full-analysis` | 一次性全面体检 | 本技能用于长期治疗；体检可作为周期基线 |

**不做什么**：不追求一次性清零；不在循环内做需要业务裁决的语义变更；不把“重复”简单等同于“必须合并”。

## 2. 核心模型

```text
Cycle（周期，例如每周/每月）
├─ Round 1..N（每轮 = 一个目标簇 = 一个可独立回滚的提交）
│  Scan → Rank → Select → Baseline → Refactor → Verify → Review → Commit → Record
├─ Cycle Summary（指标、决策、遗留）
└─ Backlog / Decision Log / Lessons（跨周期延续）
```

- **轮次**是最小可回滚单位。一轮只处理一个目标簇，避免多目标耦合。
- **周期**有轮次上限、时间/预算上限和明确退出条件。
- **长周期**依赖状态文件与决策账本，而不是依赖单次会话记忆。

### 2.1 轮次类型

| 类型 | 目标 | 典型产物 |
|---|---|---|
| D 去重 | 完全重复的类/工具/DTO | 抽取公共实现、删除副本 |
| P 相似范式 | 结构相似但未完全一致的代码 | 公共骨架、模板方法、参数化 |
| S 结构分派 | if/switch 按数值/字符串/枚举选择不同行为 | 接口+实现、注册表、策略 |

一轮只选一种类型；跨类型改动拆成多轮。

## 3. 硬约束（HARD GATES）

1. 每轮改动前必须能编译；改动后必须能编译。
2. 每轮必须有验证：编译 + 至少一个行为/特征测试；纯数据类可用字段/列表读写测试 + 编译。
3. 不改变公开 API 与业务语义；需要改变语义的，转入决策账本，不在循环内做。
4. 每轮一个提交，可单独 revert；禁止把多个目标塞进一个提交。
5. 失败即回滚并记账；禁止“带病继续”。
6. 不合并静态可变状态；不擅自统一跨模块契约。
7. 只做最小范围改动；不顺手重构、不删除既有测试。
8. 生产库默认只读分析；写入必须有明确授权。实验库同样遵守最小改动。
9. 结构性重构（S）必须有等价性证据：黄金输出对拍、特征测试或行为对比；没有等价性证据不得提交。

违反任一条，本轮判定失败，必须回滚并记录。

## 4. 前置条件与基线

### 4.1 构建与测试基线

1. 固定 JDK/构建工具版本，确认构建命令退出码为 0。
2. 处理测试执行器：
   - 若全局 `skipTests=true`，建立脚本化/JUnitCore 测试入口，并写入 `decisions.md`。
   - 若测试框架不可用，先补最小测试入口，再进入循环。
3. 记录基线命令、耗时与产物路径。

### 4.2 分支与快照

- 创建分支：`quality-loop/<cycle-id>`。
- 记录基线 HEAD、构建耗时、测试数量。
- 确认工作区干净；未跟踪文件需说明。

### 4.3 基线指标

运行 `scripts/dup_clusters.py` 与 `code-detect-dup`，记录：

- 完全重复簇数量（按阈值与排除规则）
- 重复率（行/Token）
- 测试类/用例数量
- 构建耗时

写入 `docs/quality-loop/metrics.md` 与 `state.json`。

## 5. 状态与账本

在目标项目创建 `docs/quality-loop/`：

| 文件 | 作用 |
|---|---|
| `state.json` | 周期/轮次/预算/基线/当前状态/停止线 |
| `backlog.md` | 候选目标、评分、风险分类、状态 |
| `decisions.md` | 合并/不合并的架构决策与理由（ADR 风格） |
| `metrics.md` | 每轮指标趋势 |
| `rounds/round-{n}.md` | 单轮报告 |
| `lessons.md` | 失败与成功模式（Reflexion 错误库） |

模板见 `templates/`。

## 6. 每轮标准作业程序（SOP）

### Step 0：载入状态与预算

- 读取 `state.json`，确认轮次、预算、停止线。
- 若上一轮失败未结案，先处理失败项，不开启新目标。

### Step 1：扫描

- 运行 `scripts/dup_clusters.py`（完全重复簇）。
- 运行 `code-detect-dup`（周期级重复率）。
- 用 `code-review` / `code-detect-problem` 补充坏味道信号。
- 结果写入 `backlog.md`。

### Step 2：排序

候选评分：

```text
score = lines × copies × safety × testability
```

| 因子 | 取值建议 |
|---|---|
| lines | 目标类/簇行数 |
| copies | 副本数量 |
| safety | 纯工具/无状态 DTO=1.0；已有规范实现=1.0；接口=0.4；静态状态=0.1；部分一致=0.2 |
| testability | 可直接单测=1.0；需 Mock=0.7；仅能编译验证=0.4 |

**优先低风险、高收益、可验证**的目标；高风险目标进入决策账本，不在本轮处理。

### Step 3：选靶

- 一轮只选一个簇。
- 若簇内包含多个类，确认它们属于同一主题且可一起回滚。
- 按 `code-part-modification` 写 `requirement.md`、`impact-analysis.md`、`tasks.md`、`test-cases.md`。

### Step 4：一致性核验

- 对候选副本做“去 package 归一化”后哈希比对。
- 只有**完全一致**才进入机械抽取；有差异则转差异分析（Step 4b）。
- Step 4b：输出差异清单与业务影响，写入 `decisions.md`，本轮结束或改选其他目标。

### Step 4c：相似范式与结构分派分析（P/S）

- 对非完全一致的候选，判断是否属于同一“范式”（相同控制流、数据结构或生命周期），而不是文本相似。
- 结构分派候选：统计 `switch`/`else-if` 的分支数、分派键类型（数值/字符串/枚举）、分支是否调用不同行为。
- 输出：差异点、共享骨架、需要参数化的部分、风险分类，写入 `backlog.md` / `decisions.md`。
- 不满足“行为可等价验证”的，转入决策账本，不在本轮做。
- 可用 `scripts/pattern_scan.py` 辅助定位分派链与重复构造范式。

### Step 5：基线验证

- 改动前先编译 + 运行相关测试，确认基线通过。
- 基线不通过则停止，先修基线或记录为阻塞项。

### Step 6：分类与策略

按第 7 节决策树选择策略。**分类错误的代价高于少做一轮。**

### Step 7：实施

通用规则：

1. **先读后删**：读取源内容后再删除，禁止先删后读。
2. **API 不变**：保留类名、方法签名、返回类型；调用点零改动优先。
3. **import 处理**：
   - 替换旧 import；
   - 对同包/通配 import 的文件补显式 import；
   - 全仓检索确认无遗漏。
4. **依赖声明**：若新落点模块未被显式依赖，补显式依赖；禁止依赖“碰巧的传递依赖”。
5. **行尾一致**：迁移后保持仓库既有行尾风格。
6. **最小改动**：不顺手修无关代码；需要修的先记入 backlog。

#### 结构分派（S）实施配方

1. **先采集黄金输出**：用独立 harness 对公开入口跑一组代表性输入（覆盖全部分支、边界与默认分支），保存结果。
2. **定义分派接口**：每个分支一个实现类或 lambda；接口只暴露稳定入参与返回。
3. **用注册表替换 switch**：`Map<Key, Interface>`；键类型优先使用不可变值（枚举、字符、字符串常量）。
4. **保留公共前置逻辑**：参数回退、空值处理、单位换算、默认值留在分派之前。
5. **保留默认语义**：未命中分支返回与 `default` 相同的结果，并加测试。
6. **重构后对拍**：运行同一 harness，逐位对比黄金输出；差异必须为零。
7. **补特征测试**：锁定代表性输入、边界与未命中分支。

### Step 8：验证

- 编译所有受影响模块（含上游依赖）。
- 运行新增测试与相关既有测试。
- API/语义检查：公开方法、返回类型、空值语义、并发语义。
- 对涉及金额/精度/并发的改动，增加对拍或并发测试。

### Step 9：审查

按 `code-review` 清单检查：

- API 兼容、空值、异常、资源、并发、命名、注释。
- 是否引入新的重复或过度抽象。
- 是否有未使用的 import/类/方法。

### Step 10：提交

- 约定式提交，一轮一提交。
- 提交信息包含：目标、收敛结果、验证结论。
- 不推送远端（除非明确要求）。

### Step 11：记账

更新：

- `state.json`：轮次、指标、停止线。
- `metrics.md`：本轮数据。
- `backlog.md`：目标状态。
- `decisions.md`：新决策。
- `lessons.md`：失败/成功模式。
- `rounds/round-{n}.md`：单轮报告。

失败时：回滚 → 记录失败原因 → 同一目标最多重试一次 → 仍失败则移入 backlog 并标注阻塞原因。

## 7. 目标选择决策树

```text
候选簇
├─ 是否 if/switch 的数值/字符串/枚举路径判断？
│  ├─ 是 → 分支是否调用不同行为且可黄金对拍？
│  │  ├─ 是 → 接口+实现/注册表（结构分派 S）
│  │  └─ 否 → 保持原样或仅做映射表（不强行多态）
├─ 是否完全一致（去 package 归一化）？
│  ├─ 否 → 差异分析 → 业务裁决 → decisions.md（本轮不做）
│  └─ 是 → 是否已有规范实现？
│     ├─ 是 → 删除副本、统一 import（策略 B）
│     └─ 否 → 类型判断
│        ├─ 纯工具/无状态 DTO → 迁移到最低公共模块（策略 A）
│        ├─ 接口/契约 → 共享契约与装配可验证？是→策略 C；否→decisions.md
│        ├─ 静态可变状态 → 不合并，记录模块隔离（策略 D）
│        ├─ 死代码/无引用 → 确认无反射/配置/JSP 引用后删除（策略 F）
│        └─ 通用名冲突 → 子包/重命名兼容（策略 H）
└─ 构建/模块条件
   ├─ 模块不在 reactor 或有既有编译阻塞 → 先修构建或跳过（策略 G）
   └─ 可编译可测试 → 进入 SOP
```

## 8. 重复分类与处理策略

| 类别 | 判定 | 策略 | 禁止 |
|---|---|---|---|
| A 纯工具/无状态 DTO | 完全一致、无静态可变状态 | 迁移到最低公共模块，保留 API | 顺手改算法 |
| B 已有规范实现 | 目标模块已存在同一实现 | 删副本、统一 import | 重复造新类 |
| C 接口/契约 | 完全一致的接口 | 仅在共享契约与装配验证后合并 | 未验证 Spring/ORM 绑定就替换 |
| D 静态可变状态 | 含静态 Map/计数器/缓存 | 保持模块隔离，记录决策 | 直接合并导致状态共享 |
| E 部分一致/已分叉 | 归一化后仍有差异 | 差异分析 + 业务裁决 | 强行统一 |
| F 死代码 | 全仓无引用 | 确认无反射/配置引用后删除 | 未确认就删 |
| G 构建阻塞 | 模块不在 reactor/编译失败 | 先修构建或跳过并记录 | 带病迁移 |
| H 通用名冲突 | 多模块同名不同实现 | 子包/重命名兼容 | 直接覆盖 |
| S 结构分派 | if/switch 按数值/字符串/枚举选择不同行为 | 接口+实现/注册表，保留默认分支与前置逻辑 | 为 1–2 个分支强行多态 |
| P 相似范式 | 结构相似但未完全一致 | 先差异分析，再抽公共骨架/模板方法 | 仅凭文本相似度合并 |

## 9. 验证矩阵

| 变更类型 | 必做 | 建议 |
|---|---|---|
| 工具/常量 | 编译 + 单测 | 边界值/异常输入 |
| 数据类/DTO | 编译 + 字段/列表读写测试 | 序列化/克隆 |
| 接口/契约 | 编译 + 实现类/装配检查 | 启动冒烟 |
| 删除副本 | 全仓引用检索 + 编译 | 反射/配置扫描 |
| 并发相关 | 编译 + 并发单测 | 压力/死锁检测 |
| 金额/精度 | 编译 + 黄金样本/对拍 | 边界与舍入 |
| 消息/通道 | 编译 + 拓扑检查 | 生产者/消费者联调 |
| 结构分派（S） | 编译 + 黄金输出对拍 + 特征测试 | 边界/默认分支/空值 |
| 相似范式（P） | 编译 + 差异清单 + 回归测试 | 行为差异逐项确认 |

## 10. 质量指标与健康分

每轮记录：

- 完全重复簇数量（≥N 行，排除委托模板）
- 重复率（行/Token）
- 构建成功/失败、测试通过/失败
- 回归事故数（目标为 0）
- 本轮净减行、测试新增数
- 消除的 switch/if 分派数
- 黄金对拍用例数与一致率
- 轮次耗时

健康分示例（可按项目调整）：

```text
Health = 100
       - 20 × duplicateRate
       - 5  × (duplicateClusters / 10)
       - 20 × buildFailureRate
       - 10 × regressions
```

分档：≥85 健康；70–85 观察；50–70 需治理；<50 停止新增功能，先治理。

## 11. 退出、暂停与升级

### 单轮退出

- 成功：编译/测试/审查通过 → 提交 → 记账。
- 失败：回滚 → 记录 → 重试一次 → 仍失败则移入 backlog。

### 周期退出

- 达到轮次上限；
- 达到时间/Token 预算；
- backlog 中无“低风险且可验证”的目标；
- 连续两轮无有效产出。

### 停止线（Stop the Line）

任一触发即暂停循环并升级：

- 连续 2 次编译失败；
- 测试失败且原因不明；
- 公开 API 或数据语义被迫改变；
- 业务语义存在歧义；
- 生产环境告警或回归。

### 总体退出

- 不再存在“可安全机械消除”的重复；
- 剩余项均为接口/静态状态/部分一致，需要架构或业务决策；
- 决策账本已明确记录并分配责任人。

## 12. 周期调度（长周期执行）

| 频率 | 内容 | 轮次上限 | 目标类型 |
|---|---|---|---|
| 每周 | 常规 cycle | 3–5 轮 | 纯工具、无状态 DTO、已有规范实现 |
| 每月 | 深度 cycle | 5–8 轮 | 批量 DTO、低风险接口 |
| 每季度 | 架构评审 | 不自动执行 | 静态状态、接口契约、依赖方向 |
| CI | 门禁 | 每次提交 | 构建、测试、重复率阈值 |

- 每轮设置文件数、耗时、Token 预算；超限暂停。
- 生产发布窗口内暂停自动提交；只产出候选。
- 高风险决策必须人工确认后再进入下一周期。

## 13. 失败模式与恢复

| 失败模式 | 现象 | 恢复 |
|---|---|---|
| 先删后读 | 目标文件未生成、源文件已丢 | 回滚模块；改为先读后删 |
| 通配 import | 迁移后大量“找不到符号” | 全量扫描引用文件并补显式 import |
| 构建环境 | JDK 不符、离线缺依赖、全局跳过测试 | 固定 JDK；补本地仓库；建立独立测试入口 |
| 模块不在 reactor | `Could not find the selected project` | 单模块构建或临时加入 reactor；记录 |
| 行尾混杂 | 全文件 diff、CR 警告 | 统一为仓库既有行尾 |
| 静态状态合并 | 计数器/缓存串味、统计口径变化 | 回滚；记录为“不合并” |
| 部分副本 | 行为差异被忽略 | 先差异分析；不在循环内合并 |
| 过度抽象 | 为 1–2 处重复引入复杂框架 | 保持简单；重复不足阈值不处理 |
| 测试表演 | 只测 getter/setter 充数 | 优先行为/边界测试；DTO 可接受最小测试但不得宣称覆盖率 |
| 文本相似即抽象 | 结构相似但语义不同，合并后行为漂移 | 先差异分析；只抽真正共享的骨架 |
| 注册表遗漏默认分支 | 未命中返回 null/NPE 或错误值 | 保留原 default 语义并加测试 |
| 前置逻辑被搬进实现 | 参数回退/单位换算在分支内重复或遗漏 | 公共逻辑留在分派前 |
| lambda 捕获可变状态 | 并发下结果不稳定 | 注册表只捕获不可变常量/静态方法 |

## 15. 快速开始

1. 复制 `templates/` 到目标项目 `docs/quality-loop/`。
2. 填写 `state.json`、`backlog.md`，记录基线。
3. 运行 `scripts/dup_clusters.py --root <项目根>`。
4. 按第 6 节 SOP 执行一轮。
5. 用 `templates/loop-config.yaml` 配置周期调度。
6. 每周期结束生成 `cycle-summary.md`，更新健康分。
