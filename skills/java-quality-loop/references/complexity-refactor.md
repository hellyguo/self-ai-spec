# 复杂度热点识别与削减配方

> 目标：把“看起来复杂”变成“可度量、可验证、可回滚”的削减过程。复杂度是防腐循环的一等目标（C 类轮次）。

## 1. 复杂度启发式

当没有可靠的圈复杂度工具，或需要快速定位热点时，使用缩进启发式：

- 行首 tab 数 `>= 6`，或行首空格数 `>= 24`；
- 混合缩进按 `1 tab = 4 spaces` 折算，等效缩进 `>= 24` 命中；
- 跳过空行、纯注释行、`package`/`import`；
- 默认跳过生成的 `*Base.java`。

工具：`scripts/complexity_scan.py`。

```bash
python3 scripts/complexity_scan.py --root . --min-lines 100 --top 30
```

输出：文件、行数、高缩进行、占比、最大缩进、最深区块。

## 2. 如何解读

- 这是**热点定位**，不是精确圈复杂度；高缩进可能来自换行、格式化或链式调用。
- 优先看“高缩进行多 + 占比高 + 最大缩进深”的文件。
- 再用方法级阅读确认：最深区块是否对应一个可提取的逻辑块。
- 超大核心类（数千行）先做方法级定位，不整体重构。

## 3. 削减手法（按优先级）

### 3.1 守卫语句（early return）

把：

```java
if (condition) {
    if (another) {
        doWork();
    }
}
```

改为：

```java
if (!condition || !another) {
    return;
}
doWork();
```

适合：参数校验、空值判断、权限/开关判断。

### 3.2 提取方法

把一段有明确意图、低耦合的逻辑提取为方法；方法名表达“做什么”，而不是“怎么做”。

适合：深嵌套中的稳定子流程、重复出现两次以上的块。

### 3.3 重复深嵌套块 → 纯判定 + 动作

把重复的：

```java
if (repeatFlag) {
    record();
} else if (firstTime || severityChanged) {
    record();
}
```

提取为：

```java
static boolean shouldRecord(flag, current, existing) {
    return flag || existing == null || severityChanged(existing, current);
}

private static void recordIfNeeded(...) {
    if (shouldRecord(...)) {
        doRecord();
    }
}
```

优点：嵌套下降、重复消除、判定逻辑可单测。

### 3.4 分解条件（named boolean）

把复杂条件表达式提取为有名字的布尔变量或方法，降低阅读负担。

### 3.5 多态/注册表

当深嵌套来自“类型 → 不同行为”的分派时，按 S 类配方改为接口 + 注册表。

### 3.6 扁平化循环

嵌套循环 + 条件过滤可改为“先过滤/索引，再处理”；涉及性能时先测量，不要盲目流式化。

## 4. 不该做的

- 只把缩进改浅，逻辑仍分散在多个方法中；
- 为 1–2 行逻辑提取方法，增加跳转成本；
- 整体重写超大核心类，无法做行为对拍；
- 在性能关键的热循环中引入额外对象/流；
- 手工重构生成代码。

## 5. 验证

1. 记录重构前指标：高缩进行、最大缩进、重复块数。
2. 编译通过。
3. 行为验证：特征测试/黄金对拍/回归测试。
4. 记录重构后指标；若指标下降但方法数激增，评估是否真正降复杂度。
5. 公开 API 不变；一轮一提交。

- [ ] 高缩进行/最大缩进有下降，或复杂度转移到更可读的结构
- [ ] 重复块消除
- [ ] 行为等价性有测试或对拍
- [ ] 公开 API 未变
