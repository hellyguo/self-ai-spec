# 多轮循环经验（通用）

> 本文件总结一类真实循环实验的通用经验，不绑定具体项目。用于校准轮次节奏、目标选择与失败处理。

## 1. 实验形态

- 对象：大型多模块 Java 存量系统（百万行级）。
- 目标：验证“周期性、高强度、可回滚”的质量循环，而不是一次性清零。
- 结果：连续 9 轮，构建与测试稳定，无回归。

## 2. 轮次结果（聚合）

| 类型 | 轮次 | 收敛 | 目标类净减行 | 测试 |
|---|---|---|---|---|
| D 去重（工具/计数/线程/日期） | 3 | 81 → 3 | 1964 | 10 |
| D 去重（DTO/已有规范实现） | 7 | 30 → 10 | 3117 | 10 |
| S 结构分派（switch → 接口注册表） | 2 | 4 处 switch | 0 | 5 |
| C 复杂度（深嵌套 → 判定+动作） | 1 | 13 块 → 2 方法 | 66 | 4 |
| 合计 | 13 | 111 → 13 | 5147 | 29 |

> 说明：上表为“目标类本身”的净减行；若按提交 diff 统计（含新增公共类、测试、导入与文档），净减约 2800 行。两个口径都应在报告中注明。

## 3. 有效做法

1. **完全一致才机械处理**：去 package 归一化后哈希比对，避免合并已分叉代码。
2. **一轮一个目标、一个提交**：失败可单轮回滚，不影响其他轮。
3. **公开 API 不变**：优先保留类名/方法签名，调用点零改动。
4. **先读后删**：脚本先删后读会导致目标未生成；作为硬规则。
5. **通配 import 扫描**：迁移后“找不到符号”多来自通配 import；必须全量补显式 import。
6. **显式依赖**：部分模块靠传递依赖“碰巧”可用；迁移时补显式声明。
7. **已有规范实现优先**：目标模块已存在同一实现时，删副本比新建共享类更安全。
8. **黄金输出对拍**：结构分派改造前采集输出，改造后逐位对比，是最可靠的等价性证据。
9. **分类驱动**：先分 D/P/S、再分无状态/接口/静态状态，避免对高风险类机械合并。

## 4. 失败与阻塞

| 现象 | 根因 | 处理 |
|---|---|---|
| 迁移后无法验证 | 模块不在 reactor，且有既有编译阻塞 | 回滚，记录为阻塞项 |
| 静态状态类合并 | 改变模块隔离与统计口径 | 不合并，写决策账本 |
| 同名但内容不同的副本 | 合并会改变行为 | 先差异分析，不在循环内处理 |
| 脚本先删后读 | 目标文件未生成 | 回滚，修正脚本 |
| 全局跳过测试 | `skipTests=true` | 建立独立 JUnitCore/脚本化入口 |
| 行尾混杂 | 全文件 diff、CR 警告 | 统一为仓库既有行尾 |
| 文本相似即抽象 | 结构相似但语义不同 | 先差异分析，只抽真正共享骨架 |
| 注册表漏默认分支 | 未命中返回错误值/NPE | 保留原 default 并加测试 |

## 4.1 复杂度热点

- 无可靠圈复杂度工具时，用缩进启发式（tab≥6 / space≥24，1 tab=4 spaces）快速定位热点。
- 一次复杂度轮次削减了 13 处重复深嵌套块：高缩进行 279 → 188，最大缩进 40 → 32，净减 66 行。
- 优先选择“行数适中、逻辑可独立测试”的类；超大核心类先做方法级定位，不整体重写。
- 缩进启发式会误判换行/格式化；必须人工确认方法级结构，并结合圈复杂度或调用链评估。

## 5. 关键判断

- **可安全机械消除的重复是有限的**：工具、无状态 DTO、已有规范实现会先被消除；剩余多为接口、静态状态、已分叉副本。
- **结构相似不等于可合并**：必须同时看控制流、数据结构、生命周期。
- **结构分派不是越多态越好**：1–2 个简单分支保持原样；分支多、行为差异明确、可对拍时才值得改。
- **生成代码不手工重构**：应通过生成器/模型调整。
- **测试表演要避免**：只测 getter/setter 不代表覆盖率；结构分派必须有行为测试。

## 6. 节奏建议

| 频率 | 内容 | 轮次 |
|---|---|---|
| 每周 | 去重 + 低风险相似范式 | 3–5 |
| 每月 | 批量 DTO、低风险接口 | 5–8 |
| 每季度 | 结构分派、接口契约、静态状态评审 | 人工主导 |
| CI | 构建、测试、重复率阈值 | 每次提交 |

## 7. 治理边界

本循环只是治理的一部分，不能当作万应良方：

- 它减轻的是“重复、深嵌套、可安全抽取”的局部压力；
- 它不解决需求正确性、架构边界、测试体系、CI 门禁、可观测性与安全治理；
- 它的成功标准是“腐化速度下降、维护压力减轻”，不是“指标归零”；
- 构建/测试基线缺失时，应先做基线治理，否则循环会被环境问题拖垮。

## 8. 退出判断

- 单轮：提交或回滚。
- 周期：轮次/预算耗尽，或无低风险可验证目标。
- 总体：无可安全机械消除的重复；剩余项均已进入决策账本。**不是重复率归零。**
