# 仓库文档同步

基于 git 提交记录同步仓库文档，保持文件名、双语版本与互链一致。

## 文件规划

文件名全大写，中文版不带语言后缀，英文版以 `_en` 结尾：

| 文档 | 中文版 | 英文版 |
|------|--------|--------|
| 项目说明 | `README.md` | `README_en.md` |
| 变更记录 | `CHANGELOG.md` | `CHANGELOG_en.md` |
| 使用手册 | `MANUAL.md` | `MANUAL_en.md` |

## 互链规则

1. `README.md` 与 `README_en.md` 互链。
2. `CHANGELOG.md` 与 `CHANGELOG_en.md` 互链。
3. `MANUAL.md` 与 `MANUAL_en.md` 互链。
4. `README` 需引用同语言的 `CHANGELOG` 与 `MANUAL`：中文 README 引用中文版，英文 README 引用英文版。

## 执行流程

1. 读取 git 提交记录，确定本次需要同步的变更范围（可用 `git log` 或 `git diff`）。
2. 盘点目标文件夹现有文档，与文件规划比对。
3. 按规划重命名、补充或更新文档内容：
   - 中文版为主体，英文版与中文版语义一致。
   - 版本号、日期、变更条目保持双语一致。
4. 补齐互链。
5. 联动 `merge-agents-md` 同步 `AGENTS.md`，见下节。
6. 输出变更清单，包含新增、修改、重命名与 `AGENTS.md` 合并结果。

## 联动 AGENTS.md

文档同步完成后，必须追加执行一次 `merge-agents-md`，确保 README、CHANGELOG、MANUAL 中描述的构建命令、
目录结构与语言规范引用，与 `AGENTS.md` 保持一致。

1. 授权读取：`${AI_SPEC_ROOT}/skills/merge-agents-md/SKILL.md`，按该技能定义的模板与合并优先级执行。
2. 语言判定：用户显式指定 > 按本次变更涉及的源码文件扩展名推断；仍无法判定时询问用户，不得臆断。
3. 合并优先级遵循该技能的硬门禁：项目事实（配置、命令、路径、业务规则、接口约定）保留，通用规则与
   语言规范引用以模板为准；冲突处以项目事实优先，并在变更清单中标注冲突点。
4. `AGENTS.md` 不存在时由该技能按模板新建；已存在时只做增量合并，禁止整篇覆盖。
5. 记录结果：合并（列出新增/替换的章节）、无变更、跳过。以下情形允许跳过，但必须在变更清单中写明原因：
   - 项目无源码文件，或源码语言不在该技能支持列表内；
   - 用户明确要求本次不同步 `AGENTS.md`。
6. 该步骤的提交可与文档变更合并为一次提交，提交信息体现 `sync-repo-docs` 与 `merge-agents-md` 的联动。

## 冲突处理

1. 文件夹内布局与本规划不一致时，以本规划为准。
2. 原文件夹缺少三份文件时，自动补充 `README` 与 `CHANGELOG`，并询问是否补充 `MANUAL`。
3. 原文件夹无双语模式时，询问是否扩充为双语，不得擅自创建英文版。
4. `AGENTS.md` 缺失且语言无法判定时，先询问用户语言；用户不指定则跳过联动并记录原因，不做猜测性合并。

## 检查清单

- [ ] 三份文档均存在，命名符合规划
- [ ] 双语版本内容语义一致
- [ ] 互链完整且指向正确语言
- [ ] README 已引用 CHANGELOG 与 MANUAL
- [ ] 变更条目与 git 提交记录对应
- [ ] 已按 `merge-agents-md` 校验或合并 `AGENTS.md`；跳过时已记录原因
- [ ] 已输出变更清单
