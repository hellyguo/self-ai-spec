# 完整分析流程

对目标项目执行一次端到端的全面分析，按固定顺序串联各专项技能。

## 适用场景

- 项目接手、交接前的整体体检
- 技术债盘点与改造决策
- 定期质量评估与基线建立

## 前置条件

1. 确认目标项目根目录与源码范围。
2. 确认是否已有历史分析产物；如有，按各技能的增量规则处理。
3. 使用 skill `long-term-task` 连续执行，避免中途停顿。

## 执行顺序

各步骤存在依赖关系，不得调整顺序：

| 顺序 | 技能 | 主要输出 | 依赖 |
|------|------|----------|------|
| 1 | `code-deconstruct` | `docs/deconstruct/` | 无 |
| 2 | `code-review` | `docs/review/` | 步骤 1 的模块与数据流 |
| 3 | `code-detect-dup` | `docs/dup/` | 步骤 1 的模块划分 |
| 4 | `code-detect-problem` | `docs/detect/` | 步骤 2、3 的结果 |
| 5 | `qualitative-assessment` | `docs/assessment/` | 步骤 1 至 4 的全部输出 |

## 输出物

- 设计解构文档与图
- 代码审查报告
- 重复代码报告
- 问题评分与重构/重建方案
- 系统定性评估报告

## 完成标准

- [ ] 五个步骤均有产物且路径正确
- [ ] 后续步骤引用了前序产物，结论不相互矛盾
- [ ] 问题评分有明确依据，可从报告回溯到审查条目
- [ ] 定性评估覆盖设计、开发、运维、非功能维度
- [ ] 全部产物已 git 提交

## 注意事项

- 单个步骤失败时，记录失败原因与影响范围，不得跳过后续步骤的前提依赖。
- 分析结论必须可回溯到代码位置或量化数据，避免主观判断。
