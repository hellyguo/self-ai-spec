# 结构视角审查（内聚/耦合 + 提前固化）

> 可选视角，不是默认门禁。回答两个问题：
>
> 1. **职责和依赖放对位置了吗**（高内聚、低耦合）
> 2. **该在装配期定下来的东西，是不是被放到了运行期**（少动态判断、多提前固化）
>
> 适用：新增一个模式/分支之后、接手存量代码、重构前评估、"结构像长出来的"项目。
> 不适用：单文件小改、纯 bugfix、时间预算 < 30 分钟、已有强架构约束的项目。
> 加载方式：`Read ${AI_SPEC_ROOT}/skills/code-review/templates/structure-lens.md`。

## 一、内聚检查（可执行）

不要从"坏味道名词"出发，从**可数的证据**出发：

| 检查 | 方法 | 触发阈值 |
|---|---|---|
| 职责枚举 | 给每个类写一句话："它负责 A 和 B 和 C" | "和" ≥ 3 个 → 候选拆分 |
| 规模 | 类行数、方法行数、单方法外部依赖数 | 类 > 400 行 / 方法 > 50 行 |
| 单例穿透 | `grep -rn "X.getInstance()"` 统计调用点与文件数 | 跨 > 10 个文件 → 隐藏依赖 |
| 重复实现 | 同一语义（前缀规范化、URL 拼接、会话样板）出现次数 | ≥ 2 次 → 提取 |
| 生命周期归属 | 谁创建谁关闭；静态线程池/注册表是否有 stop | 无 stop → 资源失去归属 |

输出：类 → 一句话职责 → 建议拆成哪几个类。

## 二、耦合检查（可执行）

| 检查 | 方法 | 说明 |
|---|---|---|
| 依赖方向 | 底层协议层是否反向依赖顶层配置/工厂 | 依赖应指向稳定抽象，不指向入口 |
| 分支散落 | 同一枚举/模式判断出现在几个文件：`grep -rn "isXxxMode()"` | ≥ 3 个文件 → 缺抽象 |
| 跨层细节 | 协议层是否知道"有几种实现" | 协议层应只认接口 |
| 字符串协议 | pipeline 名、attribute key、命令名是否裸字符串 | 提取常量，拼错在编译期暴露 |
| 配置穿透 | 深层类是否直接读全局配置 | 构造注入所需片段 |

输出：耦合点 → 现状（谁依赖谁）→ 建议边界（接口/装配点）。

## 三、动态判断 → 提前固化（核心清单）

判据只有一句：**这段判断的输入，在启动/构造之后还会变吗？不会变就前移。**

| # | 类别 | 识别信号 | 固化点 | 级别 |
|---|---|---|---|---|
| 1 | 模式/策略分支 | `if (mode == X)` 出现在多个文件、或多条业务路径 | 启动期选策略对象注入 | P1 |
| 2 | 路由/枚举匹配 | 每请求 `path.equals(prefix + CONST)`、`method().name().equals(...)` | 构造期算好完整路径；用枚举 `equals` | P1 |
| 3 | 反射/动态查找 | 首次调用才 `findVirtual` / `Class.forName` | 启动期建表，找不到立即失败 | P1 |
| 4 | 字符串键 | `"handler-name"`、`"attr-key"`、命令名散落 | 常量类/枚举 | P2 |
| 5 | 默认值 | `new String(bytes)`、`getBytes()`、默认时区/Locale | 显式字符集/时区 | P2 |
| 6 | 每次重算 | 每请求拼 URL、每次归一化前缀、每次正则编译 | 构造期算好 | P2 |
| 7 | 配置校验 | 请求期才校验配置是否合法 | 启动期校验并快速失败 | P1 |

判定要点：

- 命中 1/2/3/7 且位于**每请求路径** → P1；仅在启动/每连接执行 → P2。
- 报告必须写清"改前在哪判断、改后在哪判断"，只写"建议优化"不算结论。
- 附带指标：模式判断文件数、每请求字符串比较次数、反射触发时机。

## 四、反模式与边界（必须遵守）

结构视角最容易滑向"为抽象而抽象"，以下行为需要显式拒绝：

1. **不为"少动态"把可变配置写死**——运行期确实需要改的东西（日志级别、开关）必须保持可变。
2. **不为"低耦合"引入容器/事件总线**——个人工具、单体服务里，构造注入足够。
3. **不拆强耦合状态机**——连接/缓冲/关闭共享同一份状态时，强行拆分要重新验证时序；宁可保留大类 + 补测试。
4. **动态分派是设计本身时不改**——插件注册、策略表、SPI 属于有意为之。
5. **不为结构问题引入新依赖**（DI 框架、反射库）。
6. **不改变行为**：本视角只调整结构与判定时机；协议、超时、重试语义保持原样。

## 五、输出格式

1. **指标表**：最大类/方法、单例调用点、模式分支数、重复实现数、每请求动态判断数。
2. **问题表**：级别 | 位置（文件:行） | 现象 | 固化/拆分建议。
3. **路线**：分三步，按"机械重构 → 装配期固化 → 拆类"，每步独立可验证。
4. **验证要求**：单测 + 端到端（含被改动路径之外的回归），明确写"行为未变"。
